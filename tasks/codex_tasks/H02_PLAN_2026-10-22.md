## Stage 1 — H02 in isolation
Signal exactly per the card:
- Deals → ISIN: NSE `symbol` via `symbol_isin_history` valid on the deal date; BSE `sc_code` via
  `security_master.bse_code`. Report unmatched rows/value by year. Deduplicate the same trade appearing on both
  exchanges/both feeds (same date, client, side, qty, price) and report how many.
- Net value per (isin, date, client set) = Σ buy value − Σ sell value; event = net buy ≥ ₹1 crore.
- Promoter/insider clients excluded: match client names against promoter/insider names available in the snapshot
  (PIT insider / shareholding tables, if present); report the method and match counts. If no such table exists, use
  a declared name rule (client name contains the company's own name or a "PROMOTER" token) and flag the limitation.
- **Two marquee definitions (declared now, fixed):**
  - **M1 broad institution:** the client name matches, case-insensitively, any of: `MUTUAL FUND`, ` MF `, `ASSET MANAGEMENT`,
    `AMC`, `INSURANCE`, `LIFE INSURANCE`, `PENSION`, `PROVIDENT`, `FUND`, `FUNDS`, `CAPITAL MANAGEMENT`, `INVESTMENT MANAGEMENT`,
    `SOVEREIGN`, `GOVERNMENT OF`, `MONETARY AUTHORITY`, `NORGES`, `ABU DHABI`, `GIC `, `TRUST` (exclude names also containing
    `SHARE BROKING`, `SECURITIES PRIVATE`, `STOCK BROKING`, `COMMODITIES` as these are prop/broker desks). Write the
    final regex and its hit list (top 100 clients by deal value) into the report **before computing any outcome**.
  - **M2 repeat clients:** the 20 clients with the most distinct deal-days in the **first evidence year only**
    (so the list is not chosen with future data), excluding broker/prop names as above. Log the list.
- PIT: `known_at_utc` (date only ⇒ end of day IST) → entry at **t+1 open** via the existing execution module; never the deal
  date close. Also report the next-open gap vs the deal print price (the card's main fooling risk).
- Universe U1, existing liquidity/position caps. Holding **20 and 60** trading days. Benchmark B5.
- Variants for F2/BH: {M1, M2} × {20, 60} = **4 confirmatory tests**. Placebo: deal dates shuffled within the same
  stock-year (keep identities), 499 draws, plus the label-permutation design H01 used. Report mean net excess, HAC p,
  BH q (pooled with all existing ledger tests), placebo p, year-by-year signs, top-5 payoff share, and the long book
  (kill rule, CAGR, max drawdown) as H01 did.
- Secondary (exploratory, not promotable): "less-followed" split by lagged liquidity tercile; overlap rate with H01
  result events within ±5 sessions.

## Stage 2 — H01 × H02 combination (declared now; run only after Stage 1 is complete and verified)
Base H01 leg = the retained lead: positive PAT surprise, 180-session hold (`H01_signal_assessment.md`).
Declared combinations (exactly these, 6 tests, all pooled in BH):
1. **C1 confirm:** H01 positive-PAT events that also have an M1 net-buy event in sessions [−20, +5] around the H01 trigger
   (deal must be known before entry; entry stays at the later of the two triggers' t+1 open). 180d hold.
2. **C2 confirm, M2:** as C1 with M2. 180d.
3. **C3 contrast:** H01 positive-PAT events with confirmation minus those without (same windows), M1. 180d.
4. **C4 union book:** a single long book holding H01 positive-PAT (180d) and H02 M1 (60d) events, equal weight per
   event within the existing caps; compare its CAGR/drawdown/kill with each leg alone.
5. **C5 score:** rank events by z(PAT surprise) + z(log net deal value) with **fixed weights 0.5/0.5** (no fitting);
   top tercile vs bottom tercile, 180d.
6. **C6 same as C1 at 60d hold** (to see whether the flow confirmation speeds up the drift).
"Alpha increases" is judged only by: C3 contrast > 0 with BH q < 0.05 and placebo p < 0.05, and C4 drawdown/kill no worse
than the H01 leg alone. No weight search, no window search. Value sweeps Shivam may ask for later are exploratory.
