# Task — measure GPU (GTX 1050 Ti, CuPy) against CPU (numpy) on the v4 engine workloads

## Goal
The v4 design claims that the CPU wins on the hot and nightly paths and the GPU only wins on the weekly cold tier. That claim is a thesis and has never been measured. Measure it on the pilot data, find the crossover size per workload, and write the verdict.

## Inputs
- `tasks/arch_v4/bench_screen.py` + `bench_screen.md`: the CPU benchmark and its numbers. Reuse its panel and driver loaders.
- CuPy is installed in system Python (`cupy-cuda12x[ctk]`; driver 582.78, CUDA 13.0). Check it with `python -c "import cupy; print(cupy.cuda.runtime.getDeviceCount(), cupy.cuda.Device(0).mem_info)"`.
- GPU: GTX 1050 Ti, 4 GB VRAM. ~1.2 GB is used by the desktop, so budget ≤2.5 GB.

## Do
Write `tasks/arch_v4/bench_gpu.py`. For each workload below, time numpy on CPU and CuPy on GPU:
- Report GPU time with and without host↔device transfer, and the one-time CUDA context/init cost separately.
- Use fp32 on both devices; also report fp64 on CPU for reference.
- Warm up once, then take the median of 5 runs. Synchronise the GPU before stopping the clock.
- Check correctness with `allclose(rtol=1e-4)` against numpy.

Workloads (use the real pilot panel where `bench_screen.py` does; scale with synthetic data of the same shape to find crossovers):
1. Full daily screen: residualise on 20 factors + 10 lags. Sizes: pilot (492 × 4,042 × 33), then drivers ×10, ×50.
2. A², A³ with pruning on edge matrices of 2k×500, 4k×2k, 8k×8k (if VRAM allows).
3. 3-hop shock walk, top-10: the hot path.
4. Incremental one-day update.
5. **Permutation test for the false-discovery check:** 1,000 shuffles of the full screen (the cold-tier candidate).
6. Rolling-window stability: 20 windows × 10 lags.
7. N×N covariance + top-20 eigenvectors at N = 4,042 (latent-factor extraction).

## Rules
- Read-only on all data; pilot DBs on the C: SSD only, never D:.
- Write only `tasks/arch_v4/bench_gpu.py` and `tasks/arch_v4/bench_gpu.md`.
- No installs. If CuPy fails to import or initialise in your sandbox, stop and report the exact error.
- Watch GPU memory and free it between workloads. Keep the GPU at full load for no more than ~2 minutes at a time (laptop thermals).

## Acceptance checks
- `python tasks/arch_v4/bench_gpu.py` runs to the end and writes `bench_gpu.md` containing:
  - a table per workload: CPU fp32 / CPU fp64 / GPU incl. transfer / GPU excl. transfer / speedup / allclose;
  - the CUDA init cost;
  - the crossover size per workload;
  - a final verdict listing which tier uses the GPU, backed by the numbers.

```bash
python tasks/arch_v4/bench_gpu.py
```

- The crossover sizes.
- Anything surprising.
