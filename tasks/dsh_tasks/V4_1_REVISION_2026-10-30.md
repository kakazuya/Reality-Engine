## Shivam's decisions (binding)
1. **Consensus = our own estimates; no paid feed.** Coverage of small/micro caps is thin, so:
   - Define `own_estimate`: per company, per atom, per period. Its inputs:
     - the trend from our own quarterly series;
     - adjustment by guidance claims (concall/deck);
     - where it exists, analyst numbers from the opinions DB (Drive research reports).
   - Each estimate stores its method, inputs and `known_at`.
   - "Beat/miss" is measured against `own_estimate`, and against the opinions-DB report when one exists.
   - Replace `absent.consensus` / `absent.price_target` with this.
2. **Extraction vocabulary: exhaustive surface, few labels.** We build it ourselves from our own documents.
   - **Surface layer:** every extracted phrase is kept verbatim in the lexicon; it is unlimited and grows automatically.
   - **Label layer:** ~60–80 topics in two levels, sharing ids with the registry atoms so claims join to numbers.
   - **Facets** instead of more labels: direction, magnitude, horizon, certainty, guidance-vs-fact.
   - **Choosing the label count:** cluster the phrases, then pick the smallest topic set covering ≥95% of phrases with hand-checkable precision. The remainder is stored as `other:<raw>`, and a growing `other` cluster is promoted to a topic.
   - Specify the pipeline, tables and the coverage/precision check. Run a first measured pass on the pilot's existing extracted phrases (cc_items, deck metrics, AR categories), read-only, and report: phrases, clusters, topics needed for 95%, and 20 sample mappings for a hand check.
3. **NOT IN DATA is not an answer by itself.** The gate does NOT count a typed NID as answered. Every NID goes through a triage:
   - (a) the data can be fetched free within one day → it is a fetch job;
   - (b) the data is genuinely hard to get → answer from a proxy or workaround from other held sources, labelled as an estimate with its assumption;
   - (c) only then NID, listing what was tried.

   Rewrite the coverage ceiling, the data-gap section and the answer contract accordingly. Add a `proxy` answer type to the answer contract: the proxy, the assumption, the confidence.
   (A separate worker is triaging the 150 NID cases; reference its output path `tasks/arch_v4/NID_TRIAGE.md` and do not duplicate it.)
4. **Sector store.** The v4 doc says `sector_pit.db.company_sector_pit` is empty. That is WRONG: it has 482 rows. Check which file was read and correct the doc. The real defect is that `valid_from` is a 2019-01-01 backcast of TODAY's classification, which is hindsight. Specify the sector build:
   1. PIT history from NSE's archived classification and index-constituent files;
   2. revenue-weighted multi-sector exposure from segment data;
   3. value-chain position (inputs from AR raw-material cost shares, outputs and customer industries) feeding `edge`;
   4. statistical peers from clustering factor-residual returns;
   5. themes (thematic indices + product tags);
   6. checks (PIT validation, a 30-company hand sample, coverage).

   Estimate the effort per step honestly.
5. **The discovery backtest is hindsight-free and runs on the pilot first.** Order: pilot backtest → Shivam approves the full schema → only then the full database. Write this order into section H, and define the pilot backtest: universe, window, how `edge.known_at` is enforced, and the metrics that decide "edge / no edge".
6. **GPU vs CPU is unmeasured.** A separate GPU benchmark worker is running (`tasks/arch_v4/bench_gpu.md`). Rewrite the GPU section as a thesis with the test that decides it. Do not assert results.
