# Build the one-company gap loop (KEC), three tiers

Ticket: T-048

Goal: Build `reality_engine/gap_loop/`, an unattended loop that answers 100 questions about one company, finds why each failed, fills the gap by extraction from the company's own documents or by a formula on stored numbers, and answers again. Work is done by cheap models first and escalates only on repeated failure:

1. **Tier 1, Haiku 5.5**: each unit of work is one fresh headless session: `claude -p` with `--model claude-haiku-5-5 --effort medium --output-format stream-json --verbose`, `CLAUDE_CONFIG_DIR=C:\Users\warri\.claude-neo`, cwd the sandbox. Kill the process when context (input + cache read + cache creation tokens of any assistant event) reaches 95,000; Shivam's limit is 100k. Copy the session runner pattern from `reality_engine/scripts/doc_review_loop.py` (`run_batch`, `context_of`, `child_env`, usage-limit sleep); reuse it by import or by moving it into a shared module, not by a third copy.
2. **Tier 2, DeepSeek**: a unit that fails 3 times on Haiku (no valid JSON, over the context limit, or failing the checks below; halve the unit size after an over-limit kill) is started as a dsh worker through the existing dsh-worker code in `plugins/dsh-worker/server/` (find the function behind the MCP `start_worker`; call it from Python, do not shell into the MCP). Respect its peak-hour refusal: queue the unit and retry off-peak. One DeepSeek unit at a time.
3. **Tier 3, Opus**: a unit that also fails on DeepSeek is written to `escalations.jsonl` in the sandbox with everything tried, and the loop moves on. Add a `job_watch` entry (`reality_engine/scripts/job_watch.py add`) for the loop's log so the Opus session sees it.

Sandbox: `D:\RealityEngine\sandbox\kec_loop\` (Shivam gave full permissions inside it). It holds:
- `questions\KEC_QUESTIONS.jsonl`: 100 questions, written by Claude. Read only; never edit or reword them.
- `raw\`: copies of KEC's PDFs: `history\` (annual reports, results, decks, transcripts, results press releases, 276 material filings; file names are BSE attachment ids, map them to date and title through `bse_announcements` / `corporate_documents` in the read-only stores), `company_site_transcripts\` (earnings call transcripts from KEC's site, with `_manifest.json` giving title and date), `extra_*`.
- Everything the loop writes: `kec.db` (SQLite), `state\`, `logs\`, `reports\`.

Stages, each made of small units that fit one Haiku session:
- **Answer**: batches of at most 10 questions. The session may use the read-only `reality-data` MCP (pass `--mcp-config` with the server from `.mcp.json`; never set `REALITY_DATA_ALLOW_PAID_EMBED`), `kec.db`, and the files in `raw\` and `text\`. Output per question: status (`answered`, `partial`, `not_found`), the answer, each number with unit and period, and sources (file or doc id, page, exact quote). For a failure, a gap with one type: `text_missing` (the document is not readable as text), `not_extracted` (text is there, the number is not in any store), `needs_formula` (computable from stored numbers), `wrong_store` (the data is held but the tools did not reach it), `absent` (not in any KEC document held). Questions with no date are asked as of 2026-10-19; nothing published after that date may be used.
- **Fix**: one unit per gap group, generated by the loop from the answer output, for example "extract text of every KEC transcript from FY25 on, page by page, into `kec.db`", "extract the quarterly results table of each quarter since Q1 FY25 into `facts`", "define order intake growth as a formula over stored order intake". Scripted work (PDF text with `fitz`, OCR only where a page has no text layer) is done by Python the session writes and runs inside the sandbox; the model reads only what it must.
- **Re-answer**: rerun only the questions that were not `answered`, plus a fixed 10 already answered, as a regression check.
- The loop repeats Fix and Re-answer for at most 5 rounds, or until two rounds in a row close no gap, then stops with `DONE`.

Checks, in code, before any row is stored or any answer is counted: the quote must occur in the cited page's text; the number must occur in the quote (allow Indian digit grouping and crore/lakh words); the unit must suit the measure (a margin is a percentage, an order book is money); the period must be stated; `known_at` must come from the filing record and be on or before the as-of date. A failed check is a failed attempt for that unit.

Store: `kec.db` tables `doc_text(doc_key, page, text, method, known_at)`, `facts(measure, value, unit, period, basis, doc_key, page, quote, known_at, tier)`, `formulas(name, expression, inputs, description)`, `answers(round, qid, status, answer_json, gap_type, tier)`. Use the typed contracts in `reality_engine/contracts.py` where they fit.

Reports: after each round write `reports\round_N.xlsx` (one row per question: status, answer, sources, gap, tier that did it) and one line per round to the log: answered, partial, not found, gaps closed, units by tier, Haiku tokens, DeepSeek jobs, escalations. Log lines end with `DONE`, `STOPPED <reason>` or `PAUSED`.

Guards: never write outside the sandbox except the loop's code and tests in the repo; never edit `questions\`; never read `D:\Shivam_Private` or any key file; no network fetches (raw files are already held); no paid embedding; a budget stop at $15 estimated Haiku list price per run; usage-limit sleep 15 minutes; a keeper restart like `reality_engine/scripts/doc_review_keeper.py`.
