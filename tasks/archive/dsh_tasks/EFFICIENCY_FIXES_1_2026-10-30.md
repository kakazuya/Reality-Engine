# Task — efficiency fixes round 1: worker defaults, schema tool, git churn, failing tests

## Goal
Apply the efficiency fixes Shivam approved on 30 Oct 2026. Each is small. Evidence (183 jobs, 19,000 tool calls): about 3,900 pwsh file read/search/list calls, about 860 inline DB queries via pwsh, 421 schema probes (56 failed), and each gate run commits about 5,600 changed lines.

## Fixes
1. **Standing instruction.** Extend `CODE_INTEL_INSTRUCTION` in `plugins/dsh-worker/server/core.py`: besides LSP first, use the read/grep/glob tools rather than pwsh for files; `mcp__reality-data__sql` rather than inline Python for read-only DB queries; `schema` (fix 3) rather than PRAGMA probes; send independent read-only calls in one parallel batch. Keep it short, since every brief carries it.
2. **`context_pack` on by default** in `start_worker`, opt-out with `context_pack=false`. Update the docstring and tests.
3. **Schema tool.** Add `schema(table, db=None)` to the reality-data MCP server (find it with `module_map("plugins")`): columns, types, row count, indexes, sample keys for one table, in a compact result, with a miss returning the nearest table names. Reuse the catalog's cached data. Do not make it depend on a warm search index. Also trim what `catalog()` returns by default: it returned 97,533 chars tonight and overflowed the caller's limit. Add a `db=` or `query=` filter, and make the default a one-line-per-database summary.
4. **Git churn.**
   - Gate result JSONLs (`tasks/answer_bench/GATE_RESULTS_*.jsonl`, `tasks/pilot60/RESULTS_HAND60*.jsonl`): stop tracking them; gitignore them; keep files in place so the grader still finds them. Keep `GATE_RUN_*.md` tracked. Make sure nothing in the code needs them to be tracked. To keep comparisons possible, the gate run should write a small tracked `GATE_SUMMARY.json` (counts by blocker, bucket, sector, family) instead.
   - `tasks/worker_context/CONTEXT.md` and `tasks/worker_context/schemas/*`: generated files. Gitignore them and stop tracking them, unless the worktree flow needs them: worktrees must still get a pack (generate it in the worktree, or point at the main checkout's absolute path). Prove it with a test. The merge recipe's "commit CONTEXT.md first" step should then disappear.
   - `tasks/pilot60/**/coverage.json`, `chunks_build.json`, `known_at_check.md` generated by builds: same treatment if they are regenerated each run.
   - Do not rewrite git history. Do not touch the `Manual Dumps/` line in `.gitignore`.
5. **`reality_engine/tests/test_dsh_worker_plugin.py`:** 8 failures in the worktree/merge tests, present before last night's changes. Find the root cause and fix it. Fix the code if the code is wrong, the test if the test is stale; say which for each.
6. **`test_query_planners.py`:** pytest-style with 5 stale assertions (handoff §7). Fix them.

## Rules
- Workspace writes only. No DB writes, no installs, no paid models.
- These are privileged control-plane files: no new network calls, no widening of write scopes, no changes to lease, permission or peak-hour logic.
- Use LSP for Python navigation, read/grep tools rather than pwsh for files, and `mcp__reality-data__sql` for DB queries.
