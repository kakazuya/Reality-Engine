### Traces

**MB0345, Hindalco renewable capacity.** The gold sentence ("470 megawatts...") is in the `claim` table under topic `capacity`, and I read that row. v4 says "no claim on topic capacity at [blank]". `as_of` is blank, so `known_at <= ''` removes every row (`execute.py:431`, `:626`). Data present, filter bug. Its second part then asks for segment data the question does not need.

**MB0125#L, MB0242#L, MB0245#L, promoter holding.** `hold.pct` has rows for 39 of 60 pilot names. Grasim, Pidilite, Hindalco, Bajaj, Sun, Tata Elxsi and 15 others have none. `holding("PIDILITIND")` returns 69.18% for Sep 2026 in one call, and `holding("GRASIM")` returns 45.2%, each with a filing date. Those rows carry the old ISIN (INE318A01018, INE047A01013) while the pilot uses the new one. So a pre-split ISIN most likely fell out of the join. I inferred that from the tool output and did not trace the build.

**MB0032#L, Hindalco close on 16 Oct.** The row exists at 908.0. The question says "NSE", so the part gets `exchange=NSE`, and the `company_state_daily` rows have no exchange dim. 80 cases fail only on an exchange dim and 13 only on `basis=adjusted` (measured). The dim comes from text like "(NSE: GRASIM)", so a company label becomes a filter.

**MB0309#L, YTD high.** v4 returned 1,610.3, the high on 30 June. The true YTD high to that date is 1,620.7. This is a wrong number passed as answered: `lag=ytd` was ignored and the operator stayed `value_at`. The old engine answered this class correctly (`GATE_SAMPLE40_verdicts_20261029.json`: MB0304, MB0028). v4 has regressed on the one class that worked.

**MB0337, MB0355, MB0540, APL Apollo and SAIL.** All the gold quote's key words appear in a single pilot concall chunk (2026-05-06, 2026-08-01). v4 routes them to a `rule` with no rule, or to `fin.capex`, which is not built. Retrieval never runs, because passages are not read at all (`GATE_V4_2026-10-31.md` §8; `execute.py:672`).
